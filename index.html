21. 핵심 프로젝트: 건물 실내 길찾기

A*와 Dijkstra 실습

문제: 3층 건물에서 현재 위치부터 회의실까지 계단/엘리베이터/문/통행금지 구역을 고려한 경로를 구한다.

  1. 건물 모델에서 바닥·벽·문·계단·엘리베이터를 분류한다. 단순 triangle mesh만으로는 통행 가능 여부를 알 수 없으므로 semantic metadata가 필요하다.
  2. 건물 모델 좌표계와 지도 좌표계를 정합하고 미터 단위를 확인한다.
  3. 각 층의 walkable surface를 생성한다. 2D/2.5D grid, NavMesh, 3D voxel을 비교한다.
  4. 사용자/휠체어/운반 로봇의 반경·높이·경사·회전반경에 맞춰 장애물을 팽창시킨다.
  5. 문과 층간 포털을 그래프로 연결하고 접근성 제한을 적용한다.
  6. Dijkstra와 A*의 탐색 노드 수·경로 비용을 비교한다. 휴리스틱은 최적성 조건을 지키도록 설계한다.
  7. 경로를 스무딩하되 벽을 관통하지 않는지 재검사한다.
  8. 실시간 통행금지·혼잡·엘리베이터 대기 시간을 반영한다.
  9. 화면에 경로, 남은 거리, 층간 전환, 회전 안내를 표시한다.
  10. 불가능 경로와 위치 추정 오차를 명시한다. 데모: 복셀 크기 0.2/0.5/1.0m, agent 반경, 통로 폐쇄, 층간 수단을 바꾸고 경로 결과 비교. 복셀은 선택적 접근이며 NavMesh와의 장단점 비교가 핵심.

22. 핵심 프로젝트: 실내 가구 배치 최적화

가구 배치 실습

문제: 방의 형상과 가구 크기, 출입문 여닫이, 창문, 생활 동선을 고려해 겹침 없는 상위 배치안을 제시한다.

  1. 2D 평면도에서 방 polygon/장애물/문 회전 영역을 생성한다.
  2. 가구별 footprint, 높이, 회전 가능한 각도, 사용 공간(의자 뒤 여유 등)을 정의한다.
  3. AABB는 빠른 후보 필터, OBB/polygon intersection은 정밀 충돌에 사용한다.
  4. Hard constraint: 방 안 배치, 겹침 없음, 문 개폐, 통행 폭, 콘센트 접근.
  5. Soft score: 창문 가림 최소화, 이동 동선, 조망, 대칭, 공간 활용도, 사용자 선호.
  6. 후보 생성: 벽 정렬, 격자, 방향 샘플링, 앵커 가구 우선 배치.
  7. 탐색: CP-SAT/백트래킹/시뮬레이티드 어닐링/유전 알고리즘을 비교한다.
  8. 배치 결과마다 NavMesh/grid로 실제 동선 연결성을 검증한다.
  9. 상위 3개 배치안과 점수·제약 위반·최소 통로 폭을 설명한다.
  10. 3D 장면에 배치안을 재구성하고 카메라 투어를 제공한다. 데모: 방 폭·길이·가구 수·문 위치·우선순위 슬라이더. 최적해 보장은 솔버와 문제 모델에 의존한다.

24. 필수 개념 간 차이 — 오개념 방지

  • Vertex vs Index: vertex는 속성 데이터의 항목이고 index는 vertex buffer의 항목을 참조한다. 같은 위치라도 노멀/UV가 다르면 별도 vertex가 필요할 수 있다.
  • Mesh vs Object: mesh는 기하 데이터 및 렌더링 단위, object/entity는 변환·상태·메타데이터를 포함하는 상위 개념일 수 있다.
  • AABB vs OBB: AABB는 기준 축에 평행; OBB는 회전 가능한 축을 가진다. 둘 다 실제 메시 형상과 다르다.
  • Collision vs Overlap vs Adjacency: 접촉과 내부 침투, 근접·인접 관계는 별도 정의가 필요하다.
  • Voxel vs NavMesh: voxel은 공간 표현, NavMesh는 이동 가능한 영역의 연결 구조. 서로 대체 또는 결합할 수 있다.
  • Instancing vs Merging: 인스턴싱은 동일 지오메트리의 여러 변환을 공유, 병합은 여러 메시를 하나의 기하로 합치는 접근이다.
  • GPU 가속 ≠ 모든 계산 자동 가속: CPU 병목, 전송량, draw calls, 셰이더 복잡도에 따라 결과가 달라진다.
  • FPS ≠ GPU 처리시간: frame pacing과 CPU/GPU 병목을 함께 계측해야 한다.
  • Perspective vs Orthographic: 원근 크기 변화의 유무가 다르며 공간 측정/도면에는 정사영이 유용하다.
  • glTF vs IFC: glTF는 효율적 3D 전송/렌더링 중심, IFC는 건설 자산의 의미·관계·속성 중심.
